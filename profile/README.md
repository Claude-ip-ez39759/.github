<p>在机房段吃过亏的号，最怕的不是搬，而是搬完之后说不清到底有没有变好。感觉上是顺了，可到底是线路换了起作用，还是这几天本来就闲，没人能回答。要让结论站得住，就得在搬之前留一份基线，搬之后再按同一口径读一遍。下面这套做法适合已经有一批号、准备整体迁到自营家宽的团队。</p>
<h2>一、这里该用前后测，不是平行分组</h2>
<p>平行分组要求两组号在起点上足够像，现实中很难做到——老号的注册时间、历史行为、订阅状态各不相同，硬凑两组，差异会被账号本身的差异盖过去。</p>
<h3>前后测的逻辑</h3>
<p>同一批号，在迁移前先跑一周作为基线，迁移后再连跑四周。这样账号本身是恒定的，唯一变化的是出口，读数差异就更容易归到出口上。缺点是没法排除时间因素，所以需要一组「留守号」做参照。</p>
<h3>留守参照组的作用</h3>
<p>从同一批号里留三到五个不搬，继续跑在机房段。如果迁移组的指标改善了而留守组没变，说明是出口的功劳；如果两组同时改善，多半是平台侧或季节因素。参照组不需要多，但要一直跑，中途别换配置。</p>
<h2>二、样本怎么配</h2>
<p>样本配得好，后面读表就轻松。三条原则：同源、同任务、同负载。</p>
<h3>同源指的是注册批次接近</h3>
<p>尽量选同一两个月内注册、订阅状态相似的号。跨年度的老号和上周的新号放在一起比，结论会被账号年龄搅乱。如果实在凑不齐，就按注册月份分层，各层单独看。</p>
<h3>同负载指的是请求量对齐</h3>
<p>迁移组和留守组每天的任务条数、类型、时段都设成一样。迁移组因为换了线路初期可能更谨慎，容易不自觉减量，这时要刻意保持相同，否则读数没法比。</p>

<h3>新号对照组能回答另一个问题</h3>
<p>老号搬过去恢复得慢，是因为出口不好，还是因为老号本身包袱重？加一组全新号直接在家宽上跑，如果新号第一天就很顺，说明线路没问题，老号的迟滞来自历史。这一组不是必需，但能省掉很多争论。</p>

<h2>三、迁移动作要一次做完</h2>
<p>分几天慢慢搬，会让「迁移完成」这个时间点变得模糊，读数就切成碎片。</p>
<h3>同一时间窗内切换</h3>
<p>选定一个低峰时段，比如当地凌晨，把迁移组的号在同一小时内全部切到新出口。切换前把所有旧会话结束、Cookie 清干净、配置文件按新出口的地区重设语言与时区。切换后四小时内不做任何配置改动。</p>
<h3>切换当天降载</h3>
<p>头一天把任务量压到平时的五到六成，让登录与首次对话在低压下完成。第二天恢复到七成，第三天恢复满量。这样能区分「线路不通」和「负载过高」两种不同的失败。</p>
<h3>不要同时改两件事</h3>
<p>迁移期间最忌讳顺手把指纹、UA、任务脚本一起升级。真要改，等四周观察期结束、结论落定之后再改。否则读数一乱，前面三周的功夫白费。</p>

<h3>第一天变差别慌</h3>
<p>换出口当天指标下滑是常见现象：新网段的归属信息对平台来说是陌生的，系统会多看几眼。只要不是持续性失败，一般三到七天自然回落。真正的警报是「一周后仍不见改善」，那说明新出口本身不合用。</p>
<h3>四周是观察下限，不是上限</h3>
<p>有些号的历史包袱重，恢复要更久。四周内如果曲线还在缓慢上行，可以再延两周看看；如果四周完全走平且低于基线，就该考虑换另一批家宽线路，而不是继续等。</p>
<h3>留守组的读数别忽略</h3>
<p>如果留守组在同期也出现了明显改善，说明大环境在变，迁移组的改善要打折扣看。这种情况在平台侧调整策略时很常见，也是为什么必须有参照组。</p>
<h2>五、结论怎么用</h2>
<p>实验的价值不在「证明家宽更好」，而在「知道自己的号搬过去要多久、能好到什么程度」。把这两个数字写进迁移计划：预期多久恢复，就按多久排期；恢复不到预期，就在第几周启动备用线路。</p>
<h3>把结论变成切换阈值</h3>
<p>建议设三条线：第一周验证率降到基线的一半，视为方向正确；第二周中断率降到 3% 以下，视为可用；第四周成功率高于 96%，视为完成迁移。任一节点未达，暂停扩大迁移范围，先查原因。</p>
<h2>常见问答</h2>
<h3>没有条件留参照组怎么办？</h3>
<p>答：那就把观察期拉长，并和迁移前的同一批号做严格前后对比。同时记录平台侧是否有公开的策略变更公告，尽量排除时间因素。结论的可信度会低一些，但仍比凭感觉强。</p>
<h3>迁移当天指标掉得厉害，要不要马上切回去？</h3>
<p>答：先看失败的性质。如果是连接超时、认证失败，属于线路问题，尽快切回；如果是二次验证变多但能通过，属于过渡期现象，观察三到七天再说。切回去再搬一次，反而会多留一段杂乱记录。</p>
<h3>自营家宽的延迟比机房高，会不会影响体验？</h3>
<p>答：会有影响，但通常不是主要矛盾。家宽延迟高一些属于正常，关键看成功率与中断率。如果业务对响应时间敏感，可以在选线路时优先挑同城或邻近城市的出口。</p>
<h3>实验结果能直接用于下一批号吗？</h3>
<p>答：可以参考趋势，不要照抄数字。下一批号的注册时间、历史行为不同，恢复速度会有差异。建议每批新号迁移时仍保留三天的密集观察。</p>
